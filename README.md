# CAU 选课余量监控助手

面向中国农业大学正选阶段的课程余量查询与选课辅助工具。如果体育课、通识课等课程没有抽签中，可以在遵守学校规则的前提下，用它减少重复手动刷新。
（人话：没抢到通识、体育、美育或英语的，可以试试用这个捡漏。）

本项目提供两种版本：Google Chrome 扩展插件，以及兼容 Chrome、Edge、Firefox 等浏览器的 Tampermonkey 用户脚本。两者均复用浏览器中已经登录的教务会话和学校页面原生流程，不涉及账号、密码或 Cookie 等数据。

> [!IMPORTANT]
> 本项目不能保证抢到课程，也不会绕过验证码、登录限制、选课时间、培养方案、时间冲突、课程组或其他教务规则。最终结果以学校教务系统为准。

## 选择版本

| 版本 | 适合场景 |
| --- | --- |
| Chrome 扩展 v1.4.1 | 只使用 Google Chrome，希望不依赖 Tampermonkey |
| Tampermonkey 脚本 v1.4.1 | 使用 Chrome、Edge、Firefox，或已经安装 Tampermonkey |

两个版本具备相同的核心能力。


## 插件工作模式

插件成功加载后，配置面板最上方提供两个选项卡：

- **正常模式**：保持原有行为，只显示、查询和监控一门课程。
- **多选模式**：使用标题栏右侧的“＋ 添加课程”增加待选课程块、使用“−”删除多余课程，最少 1 门、最多 4 门。每门课程均可独立填写课程名称、匹配方式、课程编号、教师、课序号、校区、时间关键词、最低余量和多班选择策略。

多选监控按 `课程 1 → 课程 2 → 课程 3 → 课程 4 → 课程 1` 循环。程序每次只把当前课程名写入教务页面并点击一次“查询”，等待共享刷新间隔和随机抖动后再查询下一门。每门课程都有独立的查询次数、匹配结果和运行状态。默认任意一门成功后停止，也可选择“一门成功后继续，直到全部待选课程都选中”。

刷新间隔、随机抖动、最大查询次数、显示已满课程、弹窗确认、桌面通知和提示音是全部课程共用的设置，只需在所有课程块下方填写一次。配置修改后会自动保存；最大查询次数按全部课程的实际查询次数合计，而不是每门分别计算。

从旧版本升级时，原来的单课程配置会自动迁移为“正常模式”的第一门课程，不需要重新填写；新增的课程块和模式选择会继续保存在各自版本原有的本地配置存储中。

## 安装

### Google Chrome 扩展

使用“加载已解压的扩展程序”，或从 [最新 Release](https://github.com/apshiap05/CAU-/releases/latest) 下载与当前版本对应的压缩包。下载后请确认 `manifest.json` 的版本为 `1.4.1`；旧 Release 不会自动包含 `main` 分支的后续更新。

### Tampermonkey 脚本

1. 浏览器安装 Tampermonkey（注意不要装了盗版的，本操作产生的后果自负！）。
2. 打开 [Tampermonkey 脚本源码](./userscript/cau-course-watcher.user.js)，复制全部内容；也可以从 Release 下载 `.user.js` 文件后导入 Tampermonkey。
3. 在 Tampermonkey 中选择“添加新脚本”，替换示例内容并保存。
4. 登录教务系统并刷新选课页面。

## 使用方法

1. 在顶部选择“正常模式”或“多选模式”。（多选模式可通过标题栏右侧的“＋ 添加课程”配置最多 4 门待选课程）
2. 输入完整课程名称。同名课程较多时，可填写教师、课序号或时间关键词。

### 配置说明

| 配置 | 含义 |
| --- | --- |
| 课程名称 | 必填；“智能精确”允许 `羽毛球` 匹配 `羽毛球（1）`，输入自身带班号时会严格区分。 |
| 教师、课程编号、课序号、校区、时间 | 可选；同名多班时建议至少增加课序号或教师。 |
| 刷新间隔 | 默认 5 秒，最低 3 秒，并加入随机抖动。 |
| 最低余量 | 每门课程独立设置；剩余容量达到该数字时才准备选课，默认 1。 |
| 最多查询次数 | `0` 表示不限。 |
| 多班选择策略 | 每门课程独立设置；可以选择余量最多的班，或者结果页面中的第一班。 |
| 显示已满课程 | 便于观察目标课程的余量从 0 变为正数。 |
| 自动确认全部确定弹窗 | 仅在一次目标选课调用期间生效，包括班级确认和课程组确认。 |

3. 正常模式先点击“仅查询一次”；多选模式点击“仅轮询一轮”，按顺序核对每门课程是否正确。该按钮不会选课。
4. 勾选 “自动点击本次选课流程中的所有‘确定’弹窗”。
5. 检查全部条件后，勾选黄色区域中的“本次授权”。该授权不会保存，刷新后必须重新勾选。
6. 点击“开始监控”，在弹出的配置摘要中再次核对全部条件，确认后才会启动。发现符合最低余量的班级后，程序调用学校原生流程提交。
7. 成功后会按配置播放提示音或发送通知，请到“选课结果查看及退选”或课表中再次确认。

建议使用10s左右的查询间隔和随机抖动。更短的间隔并不保证更容易成功，反而可能触发服务器限流、会话异常或账号保护（别问我咋知道的）。

配置修改后会在鼠标离开面板时自动保存，并显示 3 秒提示；“本次授权”不会保存。面板顶部会持续显示页面、选课入口、课程表、原生选课函数和弹窗桥接的健康状态。

## 连续确认框处理

自动确认不是常驻的全页面点击器。程序只在目标课程参数经过校验、即将调用页面原生选课函数时，临时处理这一次调用产生的 `confirm` 和 `alert`：

1. 校验当前网址、通知单号、课程 ID、重修标识和课程表中的选课按钮。
2. 临时将本次流程出现的全部 `confirm` 处理为“确定”。
3. 记录每条确认文字和教务系统结果提示。
4. 调用结束、弹窗安静或达到超时上限后恢复页面原始弹窗函数。
5. 再到“选课结果查看及退选”区域验证是否真正选中。
